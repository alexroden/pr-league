# PR League — agent handover

Date: 2026-10-06. Written for a fresh agent taking over this project. Read this first, then the spec and plan below.

## What this is

A proof-of-concept Slack bot ("PR League") for a small team. Each run reads the current calendar month's PR reviews for a GitHub org, scores a roster listed in `config.yaml` (1 point per review given, 1 per review received, self-reviews score nothing, each review ID counts once), ranks players (ties share a position, next position skipped), and DMs each player their league position via Slack. No database, no scheduler, no CI — deliberately, because it's a PoC. The user wants to adjust it locally as they use it.

## The one decision waiting on the user (reviewer's Important finding)

"1 point per review" counts more than people expect: GitHub creates a new review for every reply in a review-comment thread, so one review with six replies scores 7, and review bots (e.g. Copilot code review) award points to the author. The current code implements the approved spec rule exactly — this was deliberately left as the user's call. Options: count each (reviewer, PR) pair once; count only APPROVED/CHANGES_REQUESTED plus substantive COMMENTED reviews; skip logins ending `[bot]`; or accept the numbers. **Changing it changes the spec and the pinning tests (`test_several_reviews_on_one_pr_each_count`) — don't change the rule unilaterally.**
