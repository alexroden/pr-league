# PR League Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A script that reads this month's PR reviews for a GitHub org, scores a small roster (1 point per review given, 1 per review received), and DMs each player their league position on Slack.

**Architecture:** One run recomputes the whole current month from GitHub, so there is no database and no state. Pure modules (`scoring`, `rendering`) hold the logic and are unit tested. Thin `httpx` wrappers (`github`, `slack`) do the I/O and are checked by hand with `--dry-run`. `main` wires them together with the collaborators passed in.

**Tech Stack:** Python 3.12, uv, httpx, PyYAML, python-dotenv, pytest.

**Spec:** `docs/superpowers/specs/2026-10-06-pr-league-design.md`

## Global Constraints

- Python pinned to the minor version: `requires-python = ">=3.12,<3.13"`; dependencies managed with uv.
- 1 point per review given, 1 point per review received. Self-reviews score nothing. Each review ID counts once.
- Window runs from 00:00 on the 1st of the current month (machine local time) to now.
- No database, no stored state, no scheduler.
- Slack bot scope is `chat:write` only. Tokens come from `.env` (`GITHUB_TOKEN`, `SLACK_BOT_TOKEN`), never from code.
- Unit tests cover `scoring.py` and `rendering.py` only, and are written before the code. GitHub and Slack modules are checked by hand.

## Review Focus

Failure modes the spec implies but does not spell out. Each is pinned by a test in the task that owns the code.

1. GitHub logins differ in case between `config.yaml` and the API (`Alice` vs `alice`). They must match. (Task 2)
2. One reviewer submits several reviews on the same PR. The spec counts each review ID, so each scores. The test pins this behaviour; it can be farmed, and capping it is a later decision. (Task 2)
3. Start of the month or nobody has activity. Everyone is joint 1st on 0 points and nothing crashes. (Tasks 2 and 3)
4. The player leads or is tied for the lead. No "Next up" line, and the message does not name a player who is not ahead. (Task 3)
5. Singular wording: "1 point", "1 review". (Task 3)

Not covered by a unit test and checked by hand in Task 6: Slack returns HTTP 200 with `ok: false` (for example a wrong member ID). `slack.py` must raise on that, and `main` must log it and carry on.

```python
    raw = yaml.safe_load(Path(path).read_text()) or {}

    entries = raw.get("players") or []
```

```python
from collections.abc import Iterable, Sequence

from pr_league.models import Player, ReviewEvent, Standing


def score(events: Iterable[ReviewEvent], players: Sequence[Player]) -> list[Standing]:
    roster = {p.github.lower(): p for p in players}
    given = dict.fromkeys(roster, 0)
    received = dict.fromkeys(roster, 0)
    seen: set[int] = set()

    for event in events:
        if event.review_id in seen:
            continue
        seen.add(event.review_id)
        reviewer, author = event.reviewer.lower(), event.author.lower()
        if reviewer == author:
            continue
        if reviewer in roster:
            given[reviewer] += 1
        if author in roster:
            received[author] += 1

    ordered = sorted(roster, key=lambda key: (-(given[key] + received[key]), key))
    standings: list[Standing] = []
    previous_points = None
    position = 0
    for index, key in enumerate(ordered, start=1):
        points = given[key] + received[key]
        if points != previous_points:
            position, previous_points = index, points
        standings.append(Standing(roster[key], given[key], received[key], position))
    return standings
```

```python
from collections.abc import Sequence
from datetime import date

from pr_league.models import Standing


def ordinal(n: int) -> str:
    if 10 <= n % 100 <= 20:
        suffix = "th"
    else:
        suffix = {1: "st", 2: "nd", 3: "rd"}.get(n % 10, "th")
    return f"{n}{suffix}"


def _count(n: int, word: str) -> str:
    return f"{n} {word}" if n == 1 else f"{n} {word}s"


def render_dm(me: Standing, standings: Sequence[Standing], today: date) -> str:
    week = (today.day - 1) // 7 + 1
    lines = [f"*PR League: {today.strftime('%B')}, week {week}*"]

    tied = sum(1 for s in standings if s.position == me.position) > 1
    place = ("joint " if tied else "") + ordinal(me.position)
    lines.append(
        f"You're *{place}* of {len(standings)} this month with "
        f"*{_count(me.points, 'point')}* ({_count(me.given, 'review')} given, {me.received} received)."
    )

    ahead = [s for s in standings if s.position < me.position]
    if ahead:
        nearest = max(s.position for s in ahead)
        next_up = [s for s in standings if s.position == nearest]
        names = " and ".join(s.player.github for s in next_up)
        gap = next_up[0].points - me.points
        lines.append(f"Next up: {names}, {_count(gap, 'point')} ahead of you.")

    rows = " · ".join(
        f"{s.position}. {'You' if s.player == me.player else s.player.github} ({s.points})"
        for s in standings
    )
    lines.append(f"Table: {rows}")
    return "\n".join(lines)
```

### Task 4: GitHub client

This resolves the spec's open question on API strategy. The GitHub search API lists PRs in the org updated since the window start (`org:X is:pr updated:>=DATE`), then each PR's reviews are listed and filtered to the window. This is simpler than listing every repo. The search API returns at most 1000 results, so the client warns when it hits that limit.

Not unit tested, per the spec. It is checked by hand in Task 6.

**Files:**
- Create: `src/pr_league/github.py`

**Interfaces:**
- Consumes: `ReviewEvent` from `pr_league.models`
- Produces: `GitHubClient(token: str, client: httpx.Client | None = None)` with `fetch_reviews(org: str, since: datetime) -> list[ReviewEvent]`. `since` must be timezone-aware. Reviews still `PENDING` (never submitted) and reviews by deleted accounts are skipped.

- [ ] **Step 1: Write the implementation**

`src/pr_league/github.py`:

```python
import logging
from datetime import datetime, timezone

import httpx

from pr_league.models import ReviewEvent

log = logging.getLogger(__name__)

API = "https://api.github.com"
SEARCH_LIMIT = 1000


class GitHubClient:
    def __init__(self, token: str, client: httpx.Client | None = None):
        self._http = client or httpx.Client(
            base_url=API,
            timeout=30,
            headers={
                "Authorization": f"Bearer {token}",
                "Accept": "application/vnd.github+json",
                "X-GitHub-Api-Version": "2022-11-28",
            },
        )

    def fetch_reviews(self, org: str, since: datetime) -> list[ReviewEvent]:
        events: list[ReviewEvent] = []
        for pr in self._search_prs(org, since):
            for review in self._get_paged(f"{pr['repository_url']}/pulls/{pr['number']}/reviews"):
                submitted = review.get("submitted_at")
                reviewer = review.get("user")
                if not submitted or not reviewer:
                    continue
                submitted_at = datetime.fromisoformat(submitted)
                if submitted_at < since:
                    continue
                events.append(
                    ReviewEvent(review["id"], reviewer["login"], pr["user"]["login"], submitted_at)
                )
        return events

    def _search_prs(self, org: str, since: datetime):
        day = since.astimezone(timezone.utc).date().isoformat()
        params = {"q": f"org:{org} is:pr updated:>={day}", "per_page": 100}
        url = "/search/issues"
        while url:
            response = self._http.get(url, params=params)
            response.raise_for_status()
            body = response.json()
            if body["total_count"] > SEARCH_LIMIT:
                log.warning(
                    "Search matched %d PRs but GitHub only returns the first %d; scores will be low",
                    body["total_count"], SEARCH_LIMIT,
                )
            yield from body["items"]
            url = response.links.get("next", {}).get("url")
            params = None

    def _get_paged(self, url: str):
        params = {"per_page": 100}
        while url:
            response = self._http.get(url, params=params)
            response.raise_for_status()
            yield from response.json()
            url = response.links.get("next", {}).get("url")
            params = None
```

```python
import httpx


class SlackError(Exception):
    pass


class SlackMessenger:
    def __init__(self, token: str, client: httpx.Client | None = None):
        self._http = client or httpx.Client(
            base_url="https://slack.com/api",
            timeout=30,
            headers={"Authorization": f"Bearer {token}"},
        )

    def send(self, user_id: str, text: str) -> None:
        response = self._http.post("/chat.postMessage", json={"channel": user_id, "text": text})
        response.raise_for_status()
        body = response.json()
        if not body.get("ok"):
            raise SlackError(f"chat.postMessage to {user_id} failed: {body.get('error', 'unknown')}")
```

```python
from dotenv import load_dotenv

from pr_league.config import Config, load_config
from pr_league.github import GitHubClient
from pr_league.rendering import render_dm
from pr_league.scoring import score
from pr_league.slack import SlackMessenger

log = logging.getLogger("pr_league")


def run(config: Config, github: GitHubClient, messenger: SlackMessenger | None, now: datetime) -> int:
    """Fetch, score and DM. A None messenger prints instead (dry run). Returns the failure count."""
    month_start = now.replace(day=1, hour=0, minute=0, second=0, microsecond=0)
    events = github.fetch_reviews(config.org, month_start)
    standings = score(events, config.players)

    failures = 0
    for standing in standings:
        text = render_dm(standing, standings, now.date())
        if messenger is None:
            print(f"--- would DM {standing.player.github} ({standing.player.slack}) ---\n{text}\n")
            continue
        try:
            messenger.send(standing.player.slack, text)
            log.info("DM sent to %s", standing.player.github)
        except Exception:
            failures += 1
            log.exception("DM to %s failed", standing.player.github)
    return failures


def cli() -> None:
    parser = argparse.ArgumentParser(prog="pr-league")
    parser.add_argument("--dry-run", action="store_true", help="print the DMs instead of sending them")
    parser.add_argument("--config", default="config.yaml")
    args = parser.parse_args()

    logging.basicConfig(level=logging.INFO, format="%(levelname)s %(message)s")
    load_dotenv()
    config = load_config(args.config)

    messenger = None
    if not args.dry_run:
        if not config.slack_token:
            sys.exit("SLACK_BOT_TOKEN is not set (see .env.example), or use --dry-run")
        messenger = SlackMessenger(config.slack_token)

    now = datetime.now().astimezone()
    failures = run(config, GitHubClient(config.github_token), messenger, now)
    if failures:
        sys.exit(f"{failures} DM(s) failed")
```

## Known limits

- GitHub search returns at most 1000 PRs. The client logs a warning past that, and the counts will be low. For an org with more than 1000 PRs updated in a month, the fix is to list per repo instead.
- API calls grow with the number of PRs updated this month, because every run re-reads the whole month. If that gets slow or hits rate limits, add stored state (spec, "Later").
- Time zones: the month starts at local midnight on the 1st, but the search is by UTC date, so the search window is widened by up to a day. Reviews are then filtered to the exact start, so scores are not affected.
